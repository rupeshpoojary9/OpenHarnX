## Why

Two of the four simulated users (note 21 in the vault, u1 and u3) ran Claude Code headless with `claude -p --output-format json` and never saw the hook's verdict; they found it later with `ohx report` or `ohx audit`. Their reports also said "Agent work: unknown: no agent run recorded" although the hook had run inside a Claude Code session. On READY the hook said nothing at all, and a BLOCKED agent got a 400-character note per failing check.

## Probe first

A Stop hook that only printed `{"systemMessage": ...}`, run under `claude -p` on Claude Code 2.1.281 with Haiku (about $0.02):

- `--output-format json`: no hook output anywhere; only the final result. No hook can make the verdict appear there.
- `--output-format stream-json --verbose`: the message arrives as `{"type":"system","subtype":"informational","content":"Stop says: ..."}`.

## Changed

- Every verdict reaches the person as one line with the report's path: READY ("Every check passed, the agreed acceptance tests included"), NO REGRESSIONS (as before, plus the path), each BLOCKED attempt ("BLOCKED (attempt 1 of 3); sent back to the agent with what failed"), and the stop after three attempts.
- A BLOCKED agent gets, for each failing mandatory check: the check's note, the agreed tests that failed (by name, at most 10), the error lines from the output (pytest `E` and `FAILED` lines, node, Vitest and Go failure lines; at most 12), and the path to the full output. For a regression comparison the lines come from the suite's own run (corrected 2026-10-06: until the fix below, not with exactly one regression suite). Paths inside the locked copies are turned back into project paths. The whole reason is at most 5,500 characters and says when it left something out.
- `verify` takes the agent session that asked for it; the report records `agent` (`claude-code` and the session id) and says the cost is unknown because Claude Code does not give it to hooks, and where to read it instead (`total_cost_usd` in `claude -p --output-format json`). Plain `ohx verify` is unchanged.
- README: what a blocked agent is told, and where the verdict shows with `claude -p`.

Example reason for an agent whose fix broke an existing test and missed one agreed case:

```text

```

## Validation

- `tests/test_hook_feedback.py`, 8 tests: READY told to the person with a report path that exists; each BLOCKED attempt told with its count; the agent told the failing agreed test and not the passing one, with the assertion line; full-output paths exist and hold the output; a broken existing test named with its error; the reason bounded with 62 failing tests; the report names the session with cost unknown; plain `ohx verify` names no agent. The ten existing hook tests pass unchanged.
- `./scripts/check.sh`: 531 passed, 14 skipped.
- End to end with the installed `eba9069`: a throwaway repository with an acceptance contract and `ohx hook install`, then `claude -p ... --model haiku --output-format stream-json` fixed `half()` ($0.03). The stream carried `Stop says: OpenHarnX: READY. Every check passed, the agreed acceptance tests included. Report: .../report.md`, and the report named the session. (`ohx report` afterwards was STALE because the probe wrote its own stream file into that repository after the hook ran; correct behaviour.)

## Limitations

- With `claude -p --output-format json` the verdict still cannot appear in the output; the README says to use `stream-json` or `ohx report`.
- The agent's cost stays unknown in the report. Reading it from the transcript would mean pricing tokens ourselves, which is not a recorded fact.
- Error lines are picked by patterns; an unusual runner's failure may fall back to the last five lines of output.
- The same error can appear under the locked and the working-tree regression checks, since both ran the test.
- The end-to-end run was one easy task that passed first time; the blocked path is covered by tests, not by a live agent repairing after feedback.

## Fix 2026-10-06: one regression suite (contract 0057)

Found in review: with exactly one regression suite the comparison is named plain `no-new-failures`, not `no-new-failures-<suite>`. The hook found the suite by parsing that id, so it quoted the comparison's own output (only its note) and pointed "Full output" at it: no assertion lines reached the agent. Zero setup was not affected (it makes two suites, `locked-tests` and `tests`). The brief had the same flaw, milder: it said "passed" instead of naming the suite.

The report now records which suite each comparison covers (`compares`, from the obligation's `of`), and the hook and the brief look it up there; reports from before fall back to the id. Tests: `test_with_one_regression_suite_the_agent_still_gets_its_error_lines` and `test_the_brief_names_the_one_suite_a_passing_comparison_covered` in `tests/test_hook_feedback.py`, both failing before the fix.
