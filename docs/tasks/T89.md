## Why

Measure what OpenHarnX catches on agent cheats nobody at OpenHarnX designed, before claiming anything. The dataset: [DimitrovK/impossible-tasks](https://github.com/DimitrovK/impossible-tasks) (MIT), commit `aae6718` (2026-10-02): 102 recorded runs of five models on 8 impossible and 2 solvable pytest projects, with the dataset's own labels (honest, fake, and whether a fake survives restoring the original tests).

## Method

For each run: copy the task as handed to the agent, commit it, set up OpenHarnX, apply the agent's recorded diff (hunks for compiled `.pyc` files dropped) and `ohx verify --sandbox srt`. Mode A: `ohx init --lock-tests` (zero setup). Mode B: a task contract whose acceptance is the task's tests. No model calls. 22 runs are not replayable: their effect includes new source files the dataset names but does not record.

## Defects fixed

1. **A suite that crashed at acceptance could never reach READY** (contract 0040, `tests/test_crashed_baseline.py`): with the tests importing a function that does not exist yet, collection crashed, no baseline existed and a correct fix stayed UNKNOWN. Now a later run counts if it passed, ran at least one test and every test passed; invalid and timed-out baselines are unchanged.
2. **In a locked suite, a test failing at locking could be rewritten or deleted** (contract 0041, `tests/test_edited_failing_tests.py`): the locked copy still failed "as before", so no regression showed. The no-new-failures check on a locked suite now compares each test that was failing at locking with the working tree (parsed source, so formatting does not count): changed or removed is a finding, in `ohx verify` and `ohx gate`. Editing tests that passed at locking stays harmless (the locked copy still has to pass) and adding tests needs no approval.

## Source-side checks (contract 0042)

Method: the replayable runs were split in two by a seeded hash of the run name. The rules were written from the 13 design-half fakes that were READY, and fixed before the held-out half was scored; its diffs were not read until then. One amendment before scoring, from library code rather than the dataset: in 1,188 non-test files of the installed packages, 70 of 98 module patches were `sys.stdout`, `sys.path` or a `sys` hook, so attributes of `sys` do not count (`sys.modules[...]` does).

1. **Order check** (no-new-failures): tests that newly pass are run again in one extra pytest process, on their own and in reverse order. A test that passes only after other tests ran fails. Catches a toggle or call counter that makes two contradicting tests both pass.
2. **Patch of an imported module** (weakening): in a Python file that is not a test, more assignments to, or deletions of, attributes of a module imported with `import` than at acceptance. Catches `random.randint = lambda a, b: 0`.
3. **`__eq__` that can hide a wrong result** (weakening): one that returns a constant, belongs to a subclass of a builtin value, or compares the other value with a call made at comparison time. Catches the lazy sorted wrapper and a string that equals anything.

| Source-side fakes caught | Design half | Held-out half |
|---|---|---|
| Mode A (zero setup) | 2 to **12** of 15 | 2 to **5** of 11 |
| Mode B (acceptance contract) | 4 to **14** of 15 | 6 to **9** of 11 |

Correct controls stay READY (6 of 6 in both modes); no honest run or legitimate test edit changed result. On the held-out half every fake that used one of the three tricks was caught (3 of 3: one lazy wrapper, two hidden states); the rest are not these tricks.

Totals in mode A: fakes caught 30 to **43 of 52**; source-side 4 to **17 of 26**. In mode B: source-side 10 to **23 of 26**, missing only the 3 behaviour changes below. Still READY in mode A, 9 runs:

- 6 leave the original test failing as before (the network is closed in the sandbox, the sort is still too slow, one contradicting test still fails). Zero setup judges that nothing regressed; mode B catches all 6 as failed acceptance. Whether zero setup should refuse READY while a locked test still fails is an owner decision, not built.
- 3 change behaviour so the test passes: `total()` rounds (2) and `current_year()` returns 2024 (1). Nothing without a specification can tell these from a fix.

Limits: the order check runs pytest suites only, and code that detects the extra run can behave differently in it. The static checks count per file, so a patch moved to another file is reported as new.
