## Problem

From the owner's first real `ohx bug` run: a blank screen for minutes while the agent worked. The launcher ran the agent with `subprocess.run`, so nothing was shown until it exited.

## Delivered

- **Live events.** `launch` reads the agent's output as it arrives and shows each event through a progress callback, with the elapsed time: `[0:03] read calc.py`, `run pytest -q`, `note ...`, `write proposal.md`, `edit calc.py`. Lines that are not events are kept in the record but not shown. The full output is still stored.
- **Limits up front.** `ohx bug new` starts with `investigating BUG-001: read-only, <sandbox>, time limit 15 min[, up to N agent turns, $X per run]`. Each `ohx bug fix` attempt starts with `attempt N of M: budget $B, spent $S, ...`.
- **End of each run.** `done in 12s, cost $0.03`, or `cost unknown` when the agent does not report it (never shown as zero), and the exit or stop reason.
- **Verification and next step.** `verifying the change against the locked contract`, then `attempt N: READY|BLOCKED`, the report, and `Next: ...` (approve, commit, or what to do when blocked).
- **Time limit and interruption.** The agent is killed at the time limit or when OpenHarnX is interrupted; it is never left running.
- **Proposal 13, first step.** Everything specific to Claude Code (command, model domains, credentials, configuration paths and protected configuration, event reading, cost reading) is one `AgentAdapter` definition, `CLAUDE_CODE`. The sandbox profile is built from the adapter. Claude Code now runs with `--output-format stream-json --verbose` so it emits one event per line.

## First real run (2026-10-02)

`ohx bug new` on a seeded bug (a percentage divided by 10 instead of 100), Claude Code 2.1.281 in srt: live progress worked as designed (`[0:04] run git ls-files`, `[0:16] read pricing.py`, `[0:37] write proposal.md`, notes), `done in 50s, cost $0.17`, and a correct proposal whose tests failed on the current code. `_claude_describe` needed no change.

It also found a defect: every Bash call failed with `EPERM: operation not permitted, mkdir '/private/tmp/claude-501/...'`. Claude Code keeps its shell state under a per-user directory in /tmp, not in TMPDIR, and the agent profile does not allow that. The agent fell back to reading files; in `ohx bug fix` it could not have run the tests. Fixed in the follow-up (contract 0013, `tests/test_agent_temp.py`): the adapter names the variables that move the agent's temp directory (`CLAUDE_CODE_TMPDIR` for Claude Code), and the launcher points them at the run's own writable temp directory, short (`/tmp/ohx-...`) where /tmp is writable. A test with real srt creates the directory the way Claude Code does; it fails before the fix.

## Second real run (2026-10-03)

The owner ran the full `ohx bug` loop (new, approve, fix) on a practice copy of another repository: READY in one attempt, $0.30, weakening check passed. Bash now worked inside srt in both runs. One more gap: heredocs failed ("can't create temp file for here document"), because zsh puts heredoc files under TMPPREFIX (default /tmp/zsh), not TMPDIR. Fixed in contract 0014 (`tests/test_agent_shell.py`, which runs a real zsh heredoc through real srt): the launcher sets TMPPREFIX inside the run's temp directory.

## Limits

- Seen with two real runs on two repositories; heredocs after the TMPPREFIX fix are not yet seen with the real agent.
- Tool errors (`is_error` results) are not shown as progress lines; the agent's own note is the only sign. They are in the stored output.
- Progress lines are shown only for events the adapter understands; another agent shows the banner and the done line only until it has an adapter.
- Elapsed time per event, not per tool call duration. No progress bar for verification itself (it reports when it starts and its verdict).
