## T90b: approving intended test changes (contract 0043)

A maintainer adds the `ohx-approve-tests` label (owner decision 2026-10-04). `ohx gate --approve-tests-label` looks it up with the workflow's read-only token: it counts only when its last adder can push, and when the pull request's latest pushed commit, from GitHub's workflow run records, was the judged one at the time it was added. Approved: the base's tests are not locked; the pull request's own tests must pass; a test that passed on the base and still exists must still pass; removed tests and weakening findings are recorded as approved, with who and when. The workflow reruns on `labeled` and `unlabeled` and reads with `actions: read` and `pull-requests: read` (threat model G14).

Not yet run on a real GitHub pull request: the API answers are faked in the tests. Self-approval by the person who asked the agent is allowed.

## T90a: suppressions only for checkers that run (contract 0044)

A suppression counts only when the contract runs the checker it silences: `noqa` with ruff or flake8, `type: ignore` with mypy or pyright, `pragma: no cover` with coverage (a `--cov` option on the command or in pytest's `addopts`), `@ts-ignore` with tsc, `nolint` with golangci-lint, and so on. When a command is not recognised (a script, `make`, `npm test`), every suppression counts, as before. Skips count only when unconditional; `skipif` with a condition, a skip inside an `if` or `except`, and `importorskip` do not, and skipping a test that passed is still caught by no-new-failures. What is not counted is listed in the weakening note. Baseline version 5; older baselines keep the old skip count.

On spec-kit, the 4 pull requests blocked only by this rule (merged #2825, #2394; rejected #4300, #4004) are now READY, with the suppressions listed as not counted. OpenHarnX's own contract runs ruff and mypy, so its suppressions still count. One existing test changed on purpose: a `@ts-ignore` with only `node --test` in the contract (Node strips types without checking them) is now listed instead of blocking.

## T90e: signed approval on any platform (contract 0045)

Owner question (2026-10-04): the label works only on GitHub. `ohx approve-tests` signs "test changes approved for commit X" with the maintainer's SSH key (namespace `openharnx-approval`) and stores it as a git note (`refs/notes/ohx-approvals`); `ohx gate` accepts it for exactly that commit from a key in `approvers` in the base's `ohx.toml`; `--approval-file` for CI that does not fetch notes. Threat model G15.

Found on the way: `docs/ci/README.md` said any `ohx.toml` change is caught by the weakening check; it was not. A pull request's `ohx.toml` never affected its own gate, but once merged it binds every later one, approvers included. `ohx.toml` is now check configuration (baseline version 6; older baselines judge as before).

## T90c: a check that ran other code is invalid (contract 0047)

The external review of 2026-10-04 asked for this to block, not warn. A plugin loaded into every pytest run (each xdist worker too) records where the project's modules came from: root-level modules and packages at the root or in `src/`, leaving out `tests`, `docs`, `scripts` and modules the checker loaded before the plugin (pytest itself, which a candidate file must never replace, T17). A module loaded from outside the candidate whose content differs from the candidate's own file makes the check invalid, and a regression suite that ran other code cannot be compared, so the verdict cannot pass. An identical copy (the project installed from the candidate) and modules the candidate does not have are fine.

Replayed on spec-kit #2742 with the first attempt's environment (spec-kit installed in editable mode from another checkout): READY before, UNKNOWN now, naming the files that ran from the other checkout. With the corrected environment: NO REGRESSIONS, as before. Limits: pytest only; a project module whose top folder has no `__init__.py` is not recognised.

## T90d: how many tests checked the change (contract 0048)

A test checks the change only if it passes after it; one that failed or was skipped both before and after checked nothing. The report's claims count the tests that ran, the ones that checked the change, and the ones that failed or were skipped both times, in one line ("3093 of 3145 tests checked this change; 12 failed and 40 were skipped both before and after"). Those are spec-kit #2742's numbers under srt: the 12 include the Hermes tests the sandbox stops from writing to the home folder. The failing ones are also listed by name (T91).
