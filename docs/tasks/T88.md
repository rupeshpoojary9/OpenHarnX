# T88: Four findings from an external review

```text
Task ID / requirement IDs: T88; release criteria RC-09, RC-13, RC-19; threats T7, T11
Status: done
Owner / reviewer: Rupesh Poojary / external reviewer (2026-10-03)
Exact candidate and environment: macOS 26.5.2 arm64, srt 0.0.77; Linux in the ohx-linux image under srt
```

Each finding was reproduced by a test that failed before the fix (contract 0030, `tests/test_review_findings.py`), on macOS and on Linux.

1. **The Action ran pull request code outside the sandbox (P1).** `action.yml` read the report with `python3 -c` in the candidate folder, and `-c` puts that folder first on the import path, so a pull request's `json.py` ran with the workflow step's access, even after the gate blocked it. Found on the way: the same trap in building the protected checker environment, where `python -c "import sysconfig ..."` ran in the repository and imported a candidate `sysconfig.py`. Both now run isolated (`python -I`), the second from the store. No other OpenHarnX code starts Python in the candidate outside the checker launcher, which already runs with `-P`.
2. **No collected tests gave READY (P1).** With no test collected on either side (pytest exit 5), the per-test results were two empty sets and compared as equal. Now per-test results count only when the suite ran properly (passed or had failing tests) and ran at least one test: a suite that passed at acceptance and now crashes, collects nothing or times out blocks; one that never ran properly, or ran no tests, is unavailable, never a pass.
3. **Removing signatures passed a pinned signer check (P1).** `ohx store check --signer` checked only the signatures that remained, so deleting them, editing a record and rebuilding the chain gave no problems. With a pinned key, the store must now carry a valid signature from it, and every record after its last one counts as a problem.
4. **A timed-out agent left its children running (P2).** Only the agent process was killed; its children kept the output pipe open and the launcher waited for them. The agent now runs in its own process group, and the whole group is killed when the agent exits, times out or is interrupted. Both pipes are read on threads, so the launcher keeps its own clock: after the agent ends it reads output for at most two seconds, even when a process that left the group holds a pipe open. Found by the mutation check on the first fix: its test passed with the process group switched off, because the child died writing to a closed pipe; the test child now never writes, the timeout must take under 2.5 seconds, and a second test has a child leave the group (the first fix waited 8 seconds there). A third test checks a normal run keeps its exit code and all its output (the timeout tests alone let a deadline in the past survive). Survivors left, none a gap: a thread flag that matters only at interpreter exit, the polling interval, an equivalent condition, and a shorter wait for log output after a timeout.

Limits: a process that leaves the agent's process group on purpose (a new session) is not killed; OpenHarnX stops waiting for it after two seconds. `--signer` now also fails when the last command ran without signing (`OHX_SIGNING_KEY=none`), which is the point of pinning.
