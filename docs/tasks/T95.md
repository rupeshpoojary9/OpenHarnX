## Why

There are no real users yet (owner, 2026-10-05). Four fresh agents played users: each installed OpenHarnX from a clone following only the README and `docs/`, fixed a real open issue in a real repository (python-humanize, jaraco/inflect, unjs/ufo, pypa/packaging) with Claude Code headless and OpenHarnX checking, and judged the result. One tried to cheat. Spend $1.31. Simulated users show where people get stuck and which verdicts are wrong, not adoption.

## Fixed

- **T93 (`331798e`, contract 0051):** after `ohx contract new` on a TypeScript project the contract had no regression suite, and the report still said "No regressions: yes" over 4 failing tests. `ohx contract new` now adds the project's TypeScript, JavaScript or Go suite, and the claim is made only from regression checks ("not checked" without one).
- **T94 (`9e768ad`, contract 0052):** in a project with its own virtual environment and no ohx.toml, checks ran with OpenHarnX's own interpreter (no pytest), `ohx init --lock-tests` reported success on a crashed baseline, and the report said only "crash". Checks now use the project's `.venv`, `venv` or active virtual environment; an environment problem fails `init` with the cause; a crashed check names its cause.
- **T95 (contract 0053):** after `ohx init --lock-tests`, `ohx contract new --acceptance ... --accept` replaced the locked suite with the working tree's own tests, so an existing test rewritten to expect broken output reached READY. `ohx contract new` now adds the locked copy of a Python `tests/` folder (as `ohx init --lock-tests` and `ohx gate` do) next to the working tree's own run, so the check names are `no-new-failures-locked-tests` and `no-new-failures-tests`. TypeScript, JavaScript and Go suites still run unlocked in such a contract, and the report says so.
