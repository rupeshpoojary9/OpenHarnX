## Why

The gate was Python only: the weakening check knew `# noqa` and `pytest.mark.skip` but not `// @ts-ignore` or `it.skip`, acceptance tests always ran with pytest, and per-test results came only from pytest. Most code that agents write is not only Python.

## Slices

1. TypeScript and JavaScript in local verification (done).
2. TypeScript and JavaScript in `ohx gate`: locked test files by pattern (they sit next to the code, not in `tests/`), the base's checker configuration, a protected `node_modules`, a default runner.
3. Go: `go test`, `t.Skip`, `//nolint`; needs the Go toolchain.

Playwright waits for a real user who needs it: browsers in the sandbox are their own problem.

## Slice 1: TypeScript and JavaScript locally (done)

- Weakening (baseline version 2): new `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `eslint-disable`, `biome-ignore` and coverage-ignore comments; skipped or focused tests (`.skip`, `.only`, `.fails`, `.skipIf`, `.todo`, `xit`, `fit`, `{ skip: true }`, `t.skip()`); fewer `it`/`test` calls or `expect`/`assert` calls in a test file; removed test files (`*.test.*`, `*.spec.*`, files under `__tests__/`); changed checker configuration (`tsconfig*.json`, `jsconfig.json`, Vitest, Vite, Jest, Babel, Playwright, ESLint and Biome configuration and setup files, and in `package.json` the `jest`, `eslintConfig` and similar keys and the scripts whose names start with test, lint, type, check, format, ci or verify). Version 1 baselines are compared on Python only, so contracts accepted earlier judge as they did.
- Acceptance tests: `ohx contract new --acceptance src/calc.test.ts` locks the file and runs the locked copy at its own path in a copy of the tree, because it imports the code next to it. The runner is `js_runner` from `ohx.toml`, else Vitest or Jest when `node_modules/.bin` has it, else `node --test`. The copy links the candidate's `node_modules` (git-ignored), and the report names that as a limitation.
- Per-test results: any runner that writes JUnit XML gives them through the `{junit}` placeholder in its command (Vitest `--reporter=junit --outputFile={junit}`, Node `--test-reporter=junit --test-reporter-destination={junit}`). Node's results are named by file and suite; Node 22 writes no file names, so when two of its tests share a name the per-test results are not used and the whole suite is compared (never a merged pass).
- Mutation checks stay Python only and say so.
- Evidence: `tests/test_typescript.py` (contract 0029): 33 cases. Real Vitest 3 run with `OHX_VITEST_NODE_MODULES` set. Linux under srt with Node 22: the Node 22 report format was found there (no file names) and is now a test. The mutation check's first real run on this change (`ohx verify` under srt) found 4 surviving mutants; two were real: the `node_modules` link was exercised only by the optional Vitest test, so a self-contained test with a package in `node_modules` now covers it (it fails when the link is removed). Rerun: 3 of 10 survive, none a gap: an acceptance id label (`split('.')[0]` to `[1]`), `and` to `or` in the link condition (the same behavior in every reachable case; without `node_modules` it only adds a dangling link), and a line in the mutation check that `tests/test_mutation.py` covers but this contract's acceptance tests do not.

Limits: `node_modules` comes from the candidate, outside the candidate identity, like a `.venv` without `environment = "uv"`. `ohx gate` and `ohx bug` are Python only. The patterns are text counts per file: comments and strings count too.
