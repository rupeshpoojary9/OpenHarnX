## Slice 2: TypeScript and JavaScript in `ohx gate` (done)

- Locked test files by pattern: the gate copies every TypeScript and JavaScript test file of the base (`*.test.*`, `*.spec.*`, `__tests__/`) at its path and lays them over a copy of the pull request's tree in place of the pull request's own test files (`protected_at = "."`). Python's `tests/` lock is unchanged; a project with both gets both.
- The runner comes from the base: `js_runner` in `ohx.toml`, else Vitest or Jest when `package.json` lists it, else `node --test` over `**/*.{test,spec}.{ts,mts,cts,js,mjs,cjs}` (an explicit pattern: Node's default misses `.spec` files). Vitest and Node give per-test results through `{junit}`; Jest compares the whole suite.
- `environment = "npm"`: at acceptance the base's `package-lock.json` and `package.json` are copied into the store; OpenHarnX runs `npm ci --ignore-scripts` from those copies into its own store, outside the sandbox (network needed), and every check runs in a copy of the tree linked to that `node_modules`, never the candidate's. A candidate whose `package-lock.json` differs runs nothing (invalid until a contract revision is accepted), like `uv.lock`.
- Evidence: `tests/test_typescript_gate.py` (contract 0031), with a stand-in npm: a genuine change READY; a colocated test edited to match broken code BLOCKED by the locked base copy; `test.skip`, a deleted test file and a `package.json` test script set to `true` BLOCKED; checks use the packages from the base lockfile even with a different `node_modules` planted in the checkout; a changed lockfile not READY; without the protected environment the report names the candidate's `node_modules`; the same under srt.
- Real run, 2026-10-03, macOS under srt: a Vitest 3 project with `environment = "npm"` and a real `npm ci --ignore-scripts`: a cheat (`mul` broken, its test edited to agree) BLOCKED, `no-new-failures-locked-tests` naming `src/calc.test.ts::calc > multiplies`; a genuine change with a new test READY, every check passing, no `node_modules` limitation.

Mutation check on this change: 1 of 10 survived, `env_outcome or npm_outcome` to `and` in taking the acceptance baseline: when npm cannot build the packages at acceptance, the baseline would record a failed suite instead of "unavailable"; verification then runs nothing anyway, so the verdict cannot be READY.

Limits: npm lockfiles only (pnpm and Yarn later). Jest gives no per-test results without a JUnit reporter. In CI, `npm ci` needs network outside the sandbox, from the base's lockfile only. Packages whose install scripts are needed to work (native builds) fail with `--ignore-scripts`; the gate then reports the checks failing, never READY.
