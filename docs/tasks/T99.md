## Why

In the simulated user trial (vault note 21) a skeptical user ran pypa/packaging's checks with a virtual environment outside the repository, named by an absolute `python` in `ohx.toml`. After the contract was accepted, a `.pth` file dropped into that environment's site-packages loaded a pytest plugin that turned every failure into a pass. The change, which broke a test, was READY, and the report did not name the interpreter at all: the existing limitation only covered interpreters inside the repository.

## Changed

- Accepting a contract without a locked environment records a fingerprint of the checker interpreter's environment: path, size and change time of every file in its site-packages and standard library, without `__pycache__` and `.pyc`, and of the interpreter binary and `pyvenv.cfg`. A venv's own site-packages are found from `pyvenv.cfg`; the base installation's packages count only when the venv can import them. The file list is kept in the store as a blob.
- The interpreter is asked where its code lives with `-I -S`, so no `.pth` file or `sitecustomize` in that environment runs while it is checked.
- Every verification takes the fingerprint again before anything runs. If it differs, every check is invalid, so the verdict cannot pass, and the note names the files changed, added or removed (as `site-packages/x.pth`) and says how to accept an intended change: `ohx contract accept <file>`, or `environment = "uv"`.
- A file's change time moves on any write and an ordinary user cannot set it back, so the files changed after acceptance are exactly those changed later than the fingerprint.
- Every report without a locked environment names the interpreter, wherever it is, and says what the fingerprint covers and does not.
- Threat model G17; README.

## Results

Replay of the trial's attack in the same clone of pypa/packaging and the same venv outside the repository, with the installed `96b7d3d` under srt:

| Step | Verdict |
|---|---|
| `ohx init --lock-tests` on the clean tree | locked |
| Broken source patch applied, the trial's failure-to-pass plugin planted through a `.pth` in the venv | UNKNOWN, exit 10: no check ran; every note names `site-packages/ohx_replay_cheat.py` and `site-packages/zz_replay.pth` (in the trial: READY) |
| Plant removed, broken patch kept | BLOCKED: `test_value_serialize_rejects_both_quote_delimiters` passed at acceptance and fails |

Cost of a fingerprint on this Mac: 0.09 s for a project venv (3,487 files), 2.9 s for a full conda base installation (85,140 files), taken once at acceptance and once per verification.

The previous verifier's mutation check found an untested path in T99 itself: with `and` changed to `or`, a contract without a fingerprint and without a locked environment would crash. A test for an interpreter that cannot be asked (and so has no fingerprint) was added; it fails against that change.

## Validation

- `tests/test_checker_interpreter.py`, 9 tests with a real venv outside the repository: an unchanged environment verifies and the interpreter is named; a `.pth` planted after acceptance makes every check invalid; the planted file does not run while the environment is checked; an added package, a removed file are caught; bytecode written by running the tests does not count; accepting again takes a new fingerprint; the note says how to accept an intended change; an interpreter that cannot be asked still runs the checks and says changes are not detected.
- `./scripts/check.sh`: 542 passed, 14 skipped.

## Limitations

- Changes made before the contract is accepted are part of the fingerprint, not caught by it.
- `__pycache__` and `.pyc` files are not covered: a crafted `.pyc` whose header matches its source could still run other code.
- A user with root can reset change times; the protection is against an agent running as the owner, not against root.
- Code an interpreter loads from elsewhere (`PYTHONPATH` set in the environment, a path line in a `.pth` that was there at acceptance pointing to a folder outside the fingerprint) is not covered. The trial's test venv used such a path line; files in the folder it names are not fingerprinted.
- A test suite that writes into site-packages makes every later verification invalid until the contract is accepted again.
- `environment = "uv"` remains the way to prevent this rather than detect it.
