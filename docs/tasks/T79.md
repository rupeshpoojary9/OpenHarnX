## Decisions

- 2026-10-03, owner: in CI **the base branch is the contract**. A pull request is judged against the base commit's tests, `ohx.toml` and check configuration; `--contract` can name a contract file from the base instead.
- 2026-10-03, owner (T87 item 4): CI evidence is signed as the pipeline with Sigstore keyless signing; planned as GitHub artifact attestations (slice 3).

## Slice 1: `ohx gate` (done)

- `ohx gate --base <ref> [--sandbox auto|srt|none] [--out DIR] [--contract PATH] [--home DIR]`.
- The base commit is read from a `git clone --shared`, which leaves the repository untouched. From it come `ohx.toml` (interpreter, environment, checks), the lockfile, the tests and every baseline. Nothing the pull request adds to `ohx.toml` or `contracts/` is read.
- The implied contract (new mode `gate`): `locked-tests` runs the base's `tests/` as a protected copy against the pull request's code; the base's own checks, or the pull request's `tests/` suite; each advisory suite gets its `no-new-failures` check against its result on the base; the weakening check compares the pull request with the base.
- The `gate` mode is the one contract mode without a mandatory acceptance test: its guarantee is the base's locked tests, the regression baseline and the weakening check.
- A throwaway evidence store unless `--home` keeps it; `report.json` and `report.md` in `--out`, the report appended to `$GITHUB_STEP_SUMMARY` when set; the report names the base and head commits. Exit 0 when ready, 10 otherwise. No model calls.
- Evidence: `tests/test_gate_ci.py` (contract 0021): a genuine change with a new test is READY; editing a test to match broken code, a new skip marker, loosened check configuration and a deleted test are BLOCKED; changes to `ohx.toml` and `contracts/` in the pull request have no effect; a failure already on the base does not block; the report is bound to base and head and reaches the job summary; the repository is untouched; no agent is started; and RC-30, a candidate changed during verification is invalid.

Found by the sandboxed verification: without a configuration file, pytest names each test relative to a root it derives from the working directory, which differs between the base run and the pull request run, so every locked test looked as if it no longer ran. The locked suite now runs with `--rootdir` fixed to its protected copy.

Limits so far: run without the sandbox in these tests; Linux and srt in CI are slice 2. The locked copy of `tests/` runs from outside the repository, so test packages that import each other as `tests.x` are not yet supported. In CI reports, "at acceptance" means "on the base commit".

## Slice 2a: Linux, locally in Docker (done)

- `ci/linux/Dockerfile` (Python 3.12, Node 22, srt 0.0.77, bubblewrap 0.12, socat, ripgrep, git, zsh, OpenSSH; a non-root user, as srt advises) and `ci/linux/check.sh`, which installs OpenHarnX from the read-only source, runs the whole suite with `OHX_SRT` set, and runs `ci/linux/gate_probe.py`: a sandboxed `ohx gate` on a throwaway repository.
- Result on 2026-10-03, Linux 6.10 aarch64 (Docker Desktop): **172 passed, 0 skipped**, including the real-srt and signing tests; gate probe: a genuine change READY with "enforced: checkers ran in the srt sandbox", a change that edits a test to match broken code BLOCKED.
- Docker needs three options for bubblewrap: `seccomp=unconfined` and `apparmor=unconfined` (user namespaces) and `systempaths=unconfined` (bubblewrap mounts `/proc`, which Docker masks). Without the last, srt fails with "Can't mount proc on /proc" and every checker is unavailable, which the gate reports as not enforced, never as a pass. A CI virtual machine needs none of them; Ubuntu 24.04 needs `kernel.apparmor_restrict_unprivileged_userns=0`.
- The workspace runs in memory (`--tmpfs /home/ci`), because the local Docker disk was full.

RC-02 is not yet met: it asks for Linux validated in CI, not in a local container.

## Slice 2b: GitHub Actions (done)

- `.github/workflows/gate.yml`: on `pull_request`, `ubuntu-24.04`, read-only token, no secrets, actions pinned to commit SHAs. It lifts Ubuntu 24.04's user-namespace restriction, installs bubblewrap, socat, ripgrep and srt 0.0.77, installs the gate **from the base commit** into its own environment, checks the pull request out separately, runs `ohx gate --sandbox srt`, and keeps the report as an artifact and in the job summary.
- Two draft pull requests on the private repository, 2026-10-03, both closed without merging:
  - #1, a genuine change (a new test): **READY**, "enforced: checkers ran in the srt sandbox", run 37116149741, 7.5 minutes.
  - #2, a cheat (a timed-out check counted as passed, and `test_timeout_is_unknown_not_fail_or_pass` edited to agree): **BLOCKED**, sandbox enforced, run 37116150695, 10.5 minutes. The pull request's edited test passed; the locked base copy failed, and `no-new-failures` named it, with two property tests the cheat also broke.
- Found: in CI the locked copy runs from outside the repository, so 12 tests in `test_skeleton_e2e.py` that find their fixture relative to their own file fail on the base and the pull request alike. They do not block (they failed on the base too), but the locked copy does not protect them; only the pull request's own, editable suite runs them. Release criterion RC-31; fix: run the locked copy inside a copy of the candidate tree at its real path.
- Limit: on `pull_request` the workflow file comes from the pull request, so a pull request can change the workflow. Mitigations are branch protection with the gate as a required check, and approval for workflows from outside contributors; covered by RC-18.

## RC-31: locked tests run inside the tree (done)

- The locked suite now runs in a copy of the tree as the manifest records it (tracked and untracked, not ignored), with `tests/` replaced by the locked copy, for the base baseline and for the pull request alike. Tests see the repository's layout, and pytest names them the same in both runs, so the fixed `--rootdir` is no longer needed.
- Each copied file is checked against its manifest digest; if the tree changed while it was copied, the run is invalid. The first version compared with the wrong digest function and called every file changed; it failed safe (invalid, never a pass), and a test now covers the check.
- Evidence: `tests/test_locked_in_tree.py` (contract 0022): a location-relative test passes in the locked run; editing it to match broken code is BLOCKED (READY before the fix); tests the pull request adds are not in the locked run; a copy that differs from the judged candidate is refused. On OpenHarnX itself (`ohx gate --base HEAD`): READY, `locked-tests` passed with no failing test, where the GitHub Actions run had 12.
- Limits: ignored files (generated data, `.venv`) are not in the copy; a locked test that needs them fails on the base and the pull request alike and does not block, so it is not protected.

## Slice 3: CI signing (built; active when the repository is public)

- Owner decision 2026-10-03: build now, switch on when public. GitHub's `actions/attest` README: "Artifact attestations are available in public repositories for all current GitHub plans. To use artifact attestations in private or internal repositories, you must be on a GitHub Enterprise Cloud plan." Signing through Sigstore's public instance instead would write the private repository's name and workflow to a public, permanent transparency log, so it was not used.
- `.github/workflows/gate.yml` has a separate `sign` job: it downloads the report artifact and signs `report.json` and `report.md` with `actions/attest` (SLSA provenance), binding the verdict to the workflow, repository and commit. It alone holds `id-token`, `attestations` and `artifact-metadata` write; it never checks out or runs pull request code; it runs only for public repositories and same-repository pull requests, also when the gate blocked. The gate job's summary states the signature: signed, or why not (private repository, fork).
- `tests/test_workflow_guard.py` (contract 0023) guards the workflow as text: every action pinned to a commit, a read-only default token, no write permission on the job that runs pull request code, the gate installed from the base and run under srt, the signing job never touching pull request code, signing only for public same-repository pull requests, the unsigned reasons in the summary.
- RC-24 stays not met until the first real signature, verified with `gh attestation verify report.json -R <owner>/<repo>`, after going public (T81).

## Slice 4a: GitLab and Jenkins (done)

- Owner question 2026-10-03: what do teams that do not use GitHub do? `docs/ci/README.md` (runner requirements, trust rules), `docs/ci/gitlab-ci.yml` and `docs/ci/Jenkinsfile`. Both run one identical block of commands: fetch the base when the checkout lacks it, install a pinned OpenHarnX (never the change under review), run `ohx gate --sandbox srt` with no signing key, keep `ohx-gate/`, and let the exit code be the verdict.
- `tests/test_ci_examples.py` (contract 0024) guards the block and the trust rules as text. `ci/linux/examples_probe.sh` takes the block from each example as written and runs it on Linux under srt (2026-10-03, ohx-linux image): GitLab genuine, base present: READY; GitLab cheat, base absent (fetched): BLOCKED; Jenkins genuine, base absent: READY; Jenkins cheat, base present: BLOCKED; all four "enforced: checkers ran in the srt sandbox".
- Not tested: GitLab or Jenkins themselves, which wait for a pilot. Shared container runners that cannot pass the Docker options cannot run the sandbox; the gate then reports every check unavailable, never READY.
- The repository's own `.github/workflows/gate.yml` installs the gate from the base checkout, which only works for OpenHarnX itself; other GitHub projects need a reusable action that installs a pinned version (next).

## Slice 4b: reusable GitHub Action (done, not yet run on GitHub)

- `action.yml` at the repository root, a composite action: other projects use `uses: rupeshpoojary9/OpenHarnX@<commit SHA>`. It installs the gate from its own source (`github.action_path`), so pinning the action pins the gate and the project's code is never installed; prepares the sandbox (Ubuntu 24.04's user-namespace setting, bubblewrap, socat, ripgrep, srt 0.0.77); fetches the base when the checkout lacks it; runs `ohx gate`; sets the outputs `readiness` and `report`; passes the exit code on. Inputs reach scripts only through environment variables.
- OpenHarnX's own workflow now runs the action from the base checkout (`uses: ./trusted`), so every pull request here also exercises it; the signing job is unchanged.
- `docs/ci/README.md` has a usage example with a pinned commit and a read-only token.
- Evidence: `tests/test_action.py` (contract 0025) and the updated `tests/test_workflow_guard.py`, all as text. Not yet run on GitHub: the next pull request on this repository is its first real run.

First real run of the action (PR #3, run 37119728025): the gate blocked a genuine change with every check unavailable, "checker environment unavailable: uv not found". The action installed uv into its own environment but did not put it on PATH (the old workflow had a step for that). It failed safe (unknown, never a pass); fixed by putting the environment on PATH in the gate step (contract 0026, `tests/test_action_tools.py`).
