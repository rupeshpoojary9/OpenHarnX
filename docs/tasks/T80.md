## Why

Writing a contract before every change is the cost that stops people trying the gate. T80: one command to install, one to enable; the existing suite becomes the contract; a Claude Code Stop hook runs the verification when the agent says it is done and hands BLOCKED back to it; fast enough for many loops a day.

## Slices

1. `ohx init --lock-tests` (done).
2. The Claude Code Stop hook: `ohx hook install`, and `ohx hook claude-stop` feeding BLOCKED back to the agent.
3. Speed: measure where a verification spends its time, then run only what a change can affect where that is provably safe, and say so in the report.

## Slice 1: `ohx init --lock-tests` (done)

- One command makes the project's existing test suite the contract; no contract file is written, nothing is added to the repository. It is the CI gate's contract with the working tree as the base: Python's `tests/` and every TypeScript, JavaScript and Go test file locked at its path, every test that passes now must keep passing (`no-new-failures`), the weakening check, and the project's own checks from `ohx.toml`. A new contract mode, `suite`, is like `gate`: its guarantee is the locked suite, not a new acceptance test.
- `ohx verify` then judges any change, an agent's or a person's. Changing the tests on purpose means running `ohx init --lock-tests` again, which records who locked (git user) like any acceptance.
- Locked copies are made in a temporary folder and kept only in the OpenHarnX store.
- Evidence: `tests/test_lock_tests.py` (contract 0033): one command, nothing written beside the repository, READY on the untouched tree; a test edited to match broken code BLOCKED; a genuine change with a new test READY; a removed test BLOCKED until locked again; who locked shown by `ohx audit`; a repository without tests told so; TypeScript tests next to the code locked too; under srt.
- Real run, 2026-10-03, on a copy of the owner's Bulwark practice repository under srt: `ohx init --lock-tests` in 2 seconds (183 tests in the baseline), `ohx verify` READY in about 1.3 seconds. A cheat (`_apply_redactions` changed from `>=` to `>`, its test edited to expect the broken output) BLOCKED: `no-new-failures-locked-tests` named three tests that passed at locking and fail now.

Mutation check on the first version: 6 of 10 survived; two were real: locked copies could have been written beside the repository for a TypeScript project (only the Python case checked that), and the contract could have been made as a pull request gate instead of a locked suite. Both are now tested and the mutants fail; the rest are id labels, a default for `ohx gate`, and cleanup.

Limits: the locked Python suite is `tests/` as it is in the working tree (tracked or not); TypeScript, JavaScript and Go test files are the tracked ones.
