## Item 1: a candidate file replaced the checker (VERIFY-11)

**Cause.** Checks run as `{python} -m <module>` with the candidate as working directory. Python puts that directory first on `sys.path`, so a `pytest.py`, a `pytest/` package or a module pytest imports (such as `pluggy.py`) in the candidate ran instead of the real one. The sandbox does not help: the fake is a legitimate read of the candidate.

**Reproduction first.** `tests/test_checker_shadowing.py`, locked in contract 0007. Against the code at `fb39881` all five attack cases returned READY, including the one under real srt; the four controls passed.

**Fix.** `openharnx.verify.guard_module_run` rewrites `{python} -m <module> args` to `{python} -P -c <launcher> <module> args`. The launcher requires the module to resolve before the candidate is on `sys.path` (otherwise exit 120, which is not a pass), then appends the candidate last and runs the module with `runpy`. Project code stays importable by the locked tests; the candidate cannot replace the checker or anything it imports from the interpreter's own paths.

**Results.**
- `OHX_SRT=$(which srt) uv run pytest tests/test_checker_shadowing.py`: 9 passed (includes the srt case).
- `./scripts/check.sh`: all checks passed.
- `ohx verify --sandbox srt` (frozen verifier): READY; candidate digest in the commit message.

**Contract revision.** The acceptance test was revised once after acceptance: one line exceeded the lint limit. Behavior unchanged; re-accepted as a new contract revision.

**Process note.** The drafted tests for T78 (`tests/test_progress.py`) and trace in the gate (`tests/test_trace_gate.py`) target unbuilt features and fail the checks, so they were kept out of the candidate while verifying and restored afterwards, still uncommitted.

**Limits.** See threat model T17 residual: `conftest.py`, plugins and `addopts` still run inside pytest (item 9, owner proposal 2); optional imports installed nowhere; console-script checkers are not rewritten. The frozen verifier that judged this change predates the fix.

## New gap found: item 10

The interpreter and its packages (`.venv`) sit inside the candidate directory and are git-ignored, so they are outside the candidate digest. An agent can edit the installed pytest itself. Threat model T18, open.

## Item 2: concurrent appends broke the hash chain (STATE-13)

**Cause.** `Store.append` read the idempotency key and the chain head before its write transaction began (Python's sqlite3 opens the transaction only at the first insert). Two writers could read the same head and both link to it; two writers with the same idempotency key could both pass the check.

**Reproduction first.** `tests/test_store_concurrency.py`, locked in contract 0008: 8 processes, 150 appends each, started together. Against `4203c02` the chain broke in 22 and then 33 places on two runs, and the same-key case failed.

**Fix.** The connection runs in autocommit mode with a 60 second busy timeout, and `append` opens `BEGIN IMMEDIATE` before reading the idempotency key and the chain head, then commits, or rolls back on any error. Writers now serialize on SQLite's write lock.

**Results.**
- `uv run pytest tests/test_store_concurrency.py`: 3 passed on three consecutive runs.
- `./scripts/check.sh`: all checks passed (75 passed, 3 skipped).
- `ohx verify --sandbox srt` (frozen verifier at `4203c02`): READY; candidate digest in the commit message.

**Limits.** Tested with 8 local processes on one machine and APFS; not tested on network file systems, where SQLite locking is unreliable. A writer that waits longer than 60 seconds fails with an error, which is not recorded as evidence. The review's original scale (12 writers, 3,600 events) was not rerun.

## Items 3, 5 and 6: the report trusted the store without re-checking it (GATE-09, STATE-15, GATE-10)

**Cause.** `ohx report` showed the stored verdict after checking only the candidate and the contract revision. The hash chain was checked only by `ohx store check`, which did not look at evidence files or protected copies at all.

**Reproduction first.** `tests/test_report_integrity.py`, locked in contract 0009. Against `0b96b28` all five attack cases exited READY (exit 0): a BLOCKED report edited in the store to say ready; a referenced checker output deleted; the same output rewritten; the protected acceptance copy edited; the protected copy deleted. The untouched control was READY with `store ok`.

**Fix.**
- `Store.check` also verifies every blob a record references (any key ending in `_blob`): present and matching its digest.
- `ohx store check` and `ohx report` share one integrity check: the store as above, plus every accepted protected copy against its accepted digest.
- Any integrity problem makes `ohx report` show `invalid` with the problems listed and the original verdict kept as `verified_readiness`. It outranks `stale`.

**Expected behavior changed in an existing test.** `test_skeleton_e2e.py::test_tampered_protected_copy_makes_result_unknown` tampers with the protected copy before verifying. `ohx verify` still gives unknown and blocks; `ohx report` now shows `invalid` (with `verified_readiness` unknown) instead of `unknown`. Stricter, not weaker.

**Results.**
- `uv run pytest tests/test_report_integrity.py`: 6 passed.
- `./scripts/check.sh`: all checks passed (81 passed, 3 skipped).
- New `ohx store check` on the real dogfood store: `store ok`.
- `ohx verify --sandbox srt` (frozen verifier at `0b96b28`): READY; candidate digest in the commit message.

**Limits.** The hash chain has no key, so someone who can write the store can rewrite a body, its digest and every later hash consistently; that is detected only once observations are signed (T09). Checking the whole store makes `ohx report` slower as the store grows; not measured.

## Items 4, 7 and 8: symlinks, contract text, sandbox start (STATE-14, UX-10, VERIFY-12)

Locked together in contract 0010, one acceptance file per item. Reproduced first against `fc639b8`; every control case passed before and after.

**Item 4, STATE-14 (`tests/test_symlink_identity.py`).** The manifest recorded a symlink's target path, never what it resolves to, so editing the target left the candidate digest and the report unchanged. Reproduced: a READY report on a repo whose `calc.py` links outside the repo stayed READY after the target was made buggy; the manifest digest did not change for a linked file, a file inside a linked directory, or a deleted target. Fix: each symlink entry also records what it resolves to (file digest, directory tree digest, missing, or unresolvable for loops). `MANIFEST_VERSION` is now 2, so reports made under version 1 show as stale once.

**Item 7, UX-10 (`tests/test_contract_title_text.py`).** `ohx contract new` wrote strings with `json.dumps`, which escapes emoji as surrogate pairs; TOML rejects those. Reproduced with an emoji title; accents, CJK, Devanagari, quotes, backslash, tab and DEL already worked. Fix: strings are written literally (DEL escaped), and contracts and `ohx.toml` are read and written as UTF-8 explicitly instead of in the locale's encoding.

**Item 8, VERIFY-12 (`tests/test_sandbox_start.py`).** The exit code of srt was read as the checker's result even when srt never ran the checker. Reproduced with stand-ins for srt: one that fails to start gave BLOCKED "under enforcement"; one that exits 5 gave invalid; **one that exits 0 without running anything gave READY** (worse than the review's finding). Fix: inside the sandbox the command first creates a fresh marker file; if it is missing afterwards, the outcome is `unavailable` (unknown, never pass or fail), the observation says so and the report's protection line says "not enforced" with the count. A stand-in that does run the command still gives READY.

**Results.**
- The three acceptance files: 16 passed. With `OHX_SRT` set to real srt, `tests/test_sandbox_env.py` and `tests/test_checker_shadowing.py` still pass, so the marker works under real srt.
- `./scripts/check.sh`: all checks passed (97 passed, 3 skipped).
- `ohx verify --sandbox srt` (frozen verifier at `fc639b8`): READY; candidate digest in the commit message.

**Limits.** A symlink to a large directory is hashed in full on every verify; not measured. The marker shows srt ran the shell, not that the sandbox policy was applied; policy enforcement is still covered only by the bypass suite (T05). The agent launcher does not use the marker yet.

## Item 10: the checker environment lived in the candidate (owner decision: option A)

**Cause.** Contracts ran checkers with `.venv/bin/python` from the candidate. The `.venv` is git-ignored, so it is outside the candidate digest: replacing the interpreter or an installed checker there was invisible.

**Reproduction first.** `tests/test_protected_environment.py`, locked in contract 0011. Against `21ac951`, buggy code with a fake `.venv/bin/python` that always exits 0 gave READY; 8 of 9 cases failed (the reuse case passes trivially on old code).

**Fix.** New service `openharnx.environment`. With `environment = "uv"` in `ohx.toml`:
- At acceptance, `uv.lock` is copied into the protected store and its digest recorded, like a protected test. No `uv.lock`, no acceptance.
- At verify, the candidate's `uv.lock` and the stored copy must both match the accepted digest; otherwise nothing runs and every obligation is `invalid` (unknown) until a contract revision is accepted.
- OpenHarnX builds the environment from the stored copy in a staging folder in its store with `uv sync --frozen --no-install-project --no-build`, so only locked wheels are installed and no project or package build code runs. It is reused while the lockfile, `pyproject.toml` and candidate path are unchanged.
- A `.pth` file appends the candidate (and `src/`) after the installed packages, so project code stays importable without shadowing the checker.
- If the environment cannot be built, every obligation is `unavailable`.
- Without `environment`, the report lists the blind spot: checkers ran with an interpreter inside the candidate.
- OpenHarnX's own `ohx.toml` now sets `environment = "uv"` for future contracts.

**Contract revision.** The acceptance test was revised once after acceptance. The first version called real uv inside the tests, and uv 0.8.14 panics inside the macOS sandbox (its HTTP client reads the system proxy configuration, which srt blocks), so the locked test could not run under `ohx verify --sandbox srt`. The revision uses a stand-in for uv that builds the environment with the standard library's `venv`, and adds a separate real-uv test that runs where uv can run and skips under the sandbox. The revised test was checked against `21ac951` (8 of 9 fail) before re-acceptance.

**Results.**
- `uv run pytest tests/test_protected_environment.py`: 9 passed outside the sandbox, including the real-uv test.
- Trial on this repository's own `uv.lock`: the environment built in 0.2 s from uv's cache, and ruff, mypy, lint-imports and the full test suite all passed when run from it, with `openharnx` imported through the `.pth`.
- `./scripts/check.sh`: all checks passed (106 passed, 3 skipped).
- `ohx verify --sandbox srt` (frozen verifier at `21ac951`): READY, verifier time 74 s; candidate digest in the commit message.

**Limits.**
- Building runs uv outside the sandbox, as OpenHarnX itself; it does not run under srt on macOS (uv 0.8.14 panic above). The real-uv test is skipped under the sandbox, so during `ohx verify` only the stand-in path is exercised.
- The environment lives in the OpenHarnX home. Agents OpenHarnX launches cannot write there; an unsandboxed agent with the user's full rights can. Option B (fingerprint the built environment) remains a possible second layer.
- `pyproject.toml` is not yet protected: its tool configuration is item 9.
- uv-managed projects only; other Python setups get the blind-spot line, not protection.

## Item 9: weakened checks (owner proposals 1 and 2 approved 2026-10-01)

**Cause.** Lint, type and pytest settings and `conftest.py` live in the candidate, and nothing compared suppressions, skip markers or test counts with the accepted state, so an agent could lower the bar and keep every check passing.

**Reproduction first.** `tests/test_weakening.py`, locked in contract 0012. Against `8ef34f4`, ten attacks gave READY, each making the real checker pass: a new `# noqa`; a file-level `# ruff: noqa`; `ignore = ["F401"]` added to `[tool.ruff.lint]`; a new `# type: ignore` (with mypy as a check); skip markers on the tests a broken function fails; assertions removed; a test file deleted and replaced; a root `conftest.py` that rewrites failed reports as passed; pytest `addopts` deselecting the failing tests; a new `sitecustomize.py`.

**Fix.** New service `openharnx.weakening`, and a mandatory built-in obligation `weakening` that acceptance adds to every contract (the id and `builtin` are reserved). At acceptance a baseline is recorded in the contract; at verification the candidate is compared with it. Findings, each blocking until a contract revision is accepted:
- Check configuration added, removed or changed: the `[tool]` table of any `pyproject.toml`, and `setup.cfg`, `tox.ini`, `pytest.ini`, `ruff.toml`, `mypy.ini`, `.flake8`, `.coveragerc`, `.importlinter`, `pyrightconfig.json`, any `conftest.py`, `sitecustomize.py` and `usercustomize.py`, wherever they are.
- More suppressions in a file than at acceptance: `noqa`, file-level `noqa`, `type: ignore`, `pyright: ignore`, inline `mypy:` settings, `pragma: no cover`, pytest or unittest skip and xfail markers, `pytest_plugins`.
- Fewer tests or assertions in an existing test file, or a test file removed.

New test files need no approval (proposal 1); they are checked only for suppressions. Controls: a real fix, a new test file, more tests in an existing file, and a config change approved by a contract revision are all READY.

`sitecustomize.py` is included because item 10's `.pth` puts the candidate on `sys.path`, where Python imports it at start-up.

**Expected behavior changed in two earlier acceptance tests.** `tests/test_protected_environment.py` and `tests/test_sandbox_start.py` asserted that every observation is invalid or unavailable when the environment or sandbox is broken. The built-in check uses neither and still runs, so those assertions now cover command checkers only (same number of assertions; each also requires at least one command checker). Owner approved keeping this change on 2026-10-02.

**Results.**
- `uv run pytest tests/test_weakening.py`: 14 passed.
- `./scripts/check.sh`: all checks passed (120 passed, 3 skipped).
- `ohx verify --sandbox srt` (frozen verifier at `8ef34f4`, checkers from the protected environment): see the commit message.

**Limits.**
- Counts are per file and per kind: moving a suppression within a file, or replacing one with another of the same kind, is not seen. Assertions are counted, not compared, so a weakened assertion (`== 2` to `is not None`) is not seen.
- A new test file can still change shared state at import time inside the regression run; only `conftest.py`, plugins and configuration are protected.
- Any `[tool]` change is flagged, including tightening and unrelated tools such as `[tool.uv]`; the revision is the approval path.
- Python only; TypeScript and Go are T82.
