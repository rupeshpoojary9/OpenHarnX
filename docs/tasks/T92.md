## Why

The spec-kit replay (T90) showed what the gate would have said about real agent changes, but it was a script. `ohx history` makes it a command anyone can run on their own repository: no setup beyond an interpreter, no platform API.

## What it does (contract 0049)

`ohx history [--last N] [--branch B] [--agents-only] [--config ohx.toml] [--sandbox srt]` walks the first-parent history of a branch and judges each commit against its first parent with `ohx gate`, in a throwaway clone that shares the repository's objects and leaves it untouched. A merge commit is judged with everything its pull request brought; a squashed one the same way. Changes by coding agents are marked from the author and the commit message (Copilot, Claude Code, Codex, Devin, Cursor bot accounts and co-author trailers). `--config` lends an ohx.toml to both sides, for history from before the project had one. The result is `history.md` (a table: commit, date, author, agent, verdict, tests checked, why) and `history.json`. The command reports and exits 0.

Found on the way: the T90d test count added up the locked copy and the change's own copy of the suite when pytest named the same tests differently in the two runs (a different root folder), so a gate could report twice the tests. Counts are now per suite, the largest one reported.

## Second repository: anthropics/claude-agent-sdk-python (2026-10-05)

`ohx history --last 150 --agents-only --config lent.toml --sandbox srt` on a full clone, with an environment holding the project's dependencies but not the project (`pythonpath = ["src"]` in its pytest configuration imports the candidate). 31 of the last 150 commits on `main` were marked as agent changes: 26 changelog updates by `claude[bot]` and 5 changes by people with a Claude co-author trailer.

| Verdict | Commits | What |
|---|---|---|
| NO REGRESSIONS | 28 | every changelog update; a docstring fix; a CI change |
| BLOCKED | 3 | all intended test changes: e2e-tests `conftest.py` edited (pin a model), two e2e assertions removed (CI hardening), and a fix that renamed an internal event (`_first_result_event` to `_run_ended_event`) and updated the tests that use it |

No wrong verdict, no environment failure, about 1,500 tests checking each change. Each of the 3 blocked changes needs one approval (T90b label or T90e signature). Unlike spec-kit, nothing here was rejected, so this measures friction only.

Found on the way, both fixed: from a partial clone (`--filter=blob:none`) every commit failed with the same git error; `ohx history` now refuses a shallow clone or one missing the file contents of the commits to judge, before any work, and says what to do. The first version of that guard read git's settings and advised `git fetch --refetch`, which keeps the clone partial; it now checks for the missing contents themselves.

## Limits

The checker environment is today's: old commits may need dependencies it no longer has (the spec-kit replay's `httpx`), and those runs say so rather than pass. Agent detection reads only what the commit records; an agent's change committed under a person's name without a trailer is not marked.
